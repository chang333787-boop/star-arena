## 검증

- 하네스 25/25 + 새 `harness_netcode.js` 모두 통과했습니다. 기존에 가끔 실패하던 `harness_checkpoint`도 이번에는 통과했습니다. `index.html`과 `star_arena.html`은 같은 파일입니다.
- 헤드리스 크롬(1366×610, 외부망 전면 차단)에서 부팅 시 페이지 오류가 0건이었습니다. 측정 배지가 그려지는 것도 확인했습니다.
- `harness_netcode.js` 결과는 아래와 같습니다. 60fps 시뮬레이션이고, 입력 스크립트는 이동·멈춤·대각·연타 순서입니다. 수치는 "화면 속 내 캐릭터"와 "지연 없는 진짜 내 위치"의 차이입니다.

| 상황 | 기존(이동 중 평균 / 최대) | 새 방식 | 멈춘 뒤 권한 위치와 차이 |
|---|---|---|---|
| 왕복 300ms, 흔들림 없음 | 63px / 105px | **4.3px / 9.5px** | — |
| 직통 LAN 편도 10ms | 11px / 17px | **0px / 0px** | — |
| Firebase 보통(편도 120ms ±40ms) | 50px / 93px | **5.3px / 14px** | 0.4px |
| Firebase 나쁨(편도 180ms ±80ms) | 72px / 135px | **25px / 50px** | 0.4px |
| 상태 패킷 10% 유실 | 81px / 136px | **4.7px / 60px** | 0.5px |

- **흔들림이 클 때 남는 차이**(Firebase 나쁨 25px)는 뒤로 끌림이 아닙니다. 입력이 도착한 간격이 달라서 호스트에서 **실제로 조금 다르게 움직인 것**이고, 멈추면 0.4px로 맞춰집니다. 이 차이까지 없애려면 입력에 지속 시간을 담아 보내는 방식(Source 엔진식 usercmd)이 필요한데, 호스트 시뮬레이션을 크게 바꿔야 해서 보류했습니다.
- 흔들림 없는 경우에 남는 4.3px는 입력 도착이 프레임 경계에 걸리면서 생기는 1프레임 이동량 이하의 차이입니다.
