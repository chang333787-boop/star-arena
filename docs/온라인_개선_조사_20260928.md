# 별빛 아레나 온라인(멀티플레이) 개선 조사

- 조사일: **2026-09-28** (가격·한도는 모두 이 날짜에 공식 페이지 기준으로 확인했고, 확인하지 못한 값은 **미확인**으로 표시)
- 범위: **조사만 했고 게임 코드는 바꾸지 않았습니다.** 기준 코드는 `main` 8757088 (v1.98) `index.html`이며, 아래 줄 번호도 이 버전 기준입니다.
- 부하 기준: 학급 30명, **6인 방 5개 동시**, 수업 40분(2,400초)

## 0. 한눈에 보는 결론

1. **"서버가 불안정하다"는 느낌은 원인이 세 가지 겹친 결과로 보입니다.**
   - (가) 게임 중계 통로가 **싱가포르 Firebase DB**라서 왕복 150~300ms가 걸립니다. 원래 게임 중계용으로 만든 도구가 아닙니다.
   - (나) 코드에 정석 넷코드의 부품 두 개가 빠져 있습니다.
     - 내 캐릭터를 보정할 때 **입력을 다시 적용하는 절차(화해)**가 없어서 고무줄처럼 끌려갑니다.
     - 방장이 **이전 전송이 끝났는지 보지 않고** 계속 보내서, 밀리면 지연이 쌓입니다.
   - (다) **무료 한도 소진 가능성**이 있습니다. 한 패킷이 2.5~4.4KB나 돼서, 6인 방 5개로 40분 수업을 하면 Firebase 다운로드가 **2.5~4.3GB**입니다. 무료(Spark) 한도는 **월 10GB**이고 넘으면 **그 달 말까지 DB가 멈춥니다**. 이 DB에는 **학생 계정·진행도**도 함께 들어 있어서, 온라인 대전을 많이 하면 계정 로그인까지 같이 멈출 수 있습니다.
2. **정석 구조**는 "권한 서버 + 고정 틱 + 스냅샷 보간 + 내 캐릭터 예측/화해"입니다. 별빛 아레나는 이 중 **보간과 예측은 있지만 화해가 없고**, 서버 대신 **학생 크롬북 방장**이 권한을 가집니다.
3. **무료 추천안: "지금 코드 손질(무료) → 게임 중계만 Cloudflare 무료 Durable Objects로 이전"**입니다.
   - Firebase는 로그인·로비·계정용으로 그대로 둡니다.
   - Cloudflare 무료 한도(하루 요청 10만 건)로 **하루 1~2수업**이 들어갑니다(계산은 4-2절).
   - 한국과 가까운 곳(도쿄·홍콩 등으로 추정)에 배치되고, **보내는 데이터 양에는 요금이 없습니다.**

### 1-2. 측정 방법 (선생님이 하실 수 있는 순서)

1. **Firebase 콘솔 → Realtime Database → 사용량(Usage) 탭**에서 다음을 봅니다. 돈도 안 들고 코드 수정도 필요 없는, 가장 싸고 결정적인 확인입니다.
   - 요금제가 Spark(무료)인지 Blaze인지
   - **다운로드(Downloads) 월 누적 GB**. 불안정했던 날 즈음 10GB에 닿았는지, 수업 한 번에 몇 GB가 느는지 확인합니다.
   - **동시 연결(Connections) 최고값**. 100에 닿은 적이 있는지 확인합니다.
   - **부하(Load) %**
2. **nettest.html**(저장소에 있음)을 교실 크롬북 2대로 열어 Firebase 왕복과 직통 왕복을 잽니다. 기존 현장 측정값은 직통 LAN 6ms, Firebase 150~300ms입니다.
3. **게임에 측정 표시 추가**(다음 단계에서 코드 작업). 방장·게스트가 모두 볼 수 있게 합니다.
   - 왕복 지연(ping) 평균·최대
   - 패킷 도착 간격의 흔들림(표준편차)
   - 방장 fps, 전송 대기 수
   - 초당 받은 KB
   - 몇 분 기록 후 "복사" 버튼으로 선생님께 전달
4. **증상 기록표**: 문제가 난 날짜·시각, 방 수, 방장 기기, "모두 끊김 / 한 명만 느림 / 순간이동" 중 어떤 증상인지를 적으면 위 A~L 중 무엇인지 가릴 수 있습니다.
   - 모두 끊김 → A·D
   - 한 명만 느림 → H·I
   - 순간이동 → B·C·G

### 1-3. 데이터 양 계산 (Firebase만 쓸 때, 6인 3v3)

- **게스트 1명 수신**: 15Hz × 약 2.6~4.5KB = **39~68KB/초**
- **방장 수신(입력)**: 5명 × 10~20Hz × 0.19KB = **10~19KB/초**
- **방 1개**: 5×39+10 ≈ **205KB/초** (최악 약 360KB/초)
- **40분, 방 5개**: 205KB × 2,400초 × 5 ≈ **2.5GB** (최악 **4.3GB**). PVE는 적 정보가 더해져 최악 약 7GB입니다.
- **같은 와이파이 직통이 모두 열린 경우**: Firebase는 5Hz만 쓰므로 방 5개가 40분에 약 **1GB**입니다.
- Firebase 계량에는 암호화(TLS) 오버헤드도 들어가므로 10~20%를 더 봐야 합니다.

**→ 무료 한도 10GB/월이면 직통이 안 될 때는 수업 2~4번, 직통이 될 때도 약 8~10번 만에 소진될 수 있습니다.** 넘으면 공식 안내대로 "그 달 남은 기간 동안 해당 제품 사용이 중단"됩니다.

> 이 계산은 코드로 추정한 패킷 크기로 한 것이라 실제와 다를 수 있습니다. **1-2의 ①번 콘솔 확인이 정답**입니다.

## 2. 정석 구조 정리 (실시간 대전 게임이 보통 쓰는 방식)

| 부품 | 정석 | 별빛 아레나 지금 |
|---|---|---|
| **권한 서버** | 서버 한 곳이 규칙을 계산하고, 모든 학생은 입력만 보냄. 속임수와 방장 끊김에 강함 | 학생 크롬북(방장)이 서버 역할. 방장이 끊기면 방 끝 |
| **고정 틱** | 1/30초 같은 **일정한 간격**으로 계산하고 남는 시간은 모아 둠(누산기) | 화면 프레임 간격(dt, 최대 0.05)으로 계산. 느린 기기에서는 느려짐 |
| **스냅샷 보간** | 받은 상태 2개 사이를 보간하고, 흔들림을 흡수하도록 **송신 간격×3 정도** 늦게 그림(15Hz면 약 200ms) | 있음. 120ms로 약간 짧고 탄은 보간 없음 |
| **클라이언트 예측** | 내 캐릭터는 버튼을 누르자마자 움직임 | 있음(`predictMoveAim`) |
| **화해(reconciliation)** | 서버가 "입력 #N까지 처리했다"고 알려주면, 그 위치에서 **#N 이후 내 입력을 다시 재생** | **없음**. 그냥 끌어당김(원인 C) |
| **통신 방식** | 게임 서버와 WebSocket(또는 UDP 성격의 WebRTC)으로 직접 연결. 변경분·숫자 배열로 작게 전송 | DB에 전체 스냅샷을 JSON으로 덮어쓰기 |

### 3-2. ① 지금 구조 개선만 할 때의 기대치

- 패킷을 숫자 배열로 줄이고(약 50%), 변하지 않는 값을 빼고, 1v1을 15Hz로 맞추면 Firebase만 쓸 때 방 5개가 40분에 약 **1.2~2GB**로 줄어듭니다.
- 직통까지 열리면 약 **0.5GB**가 됩니다. 이 경우 월 10GB로 **약 5~20수업**이 가능합니다(추정).
- 흐름 제어(원인 B)와 화해(원인 C)를 넣으면 "끌림·순간이동"은 크게 줄어듭니다.
- 하지만 **싱가포르 왕복 150~300ms는 코드로 줄일 수 없습니다.** 그리고 계정 DB와 한도를 계속 함께 씁니다.

### 3-3. ② Cloudflare Durable Objects 계산 (방장 권한 유지, 중계만)

- **구조**: 방마다 Durable Object(작은 서버 방) 하나를 둡니다. 방장과 게스트가 WebSocket으로 붙고, DO는 받은 것을 나눠 주기만 합니다.
- **들어오는 메시지(과금 대상)**: 방장 상태 15/초 + 게스트 입력 5명×15/초 = 방당 90/초
  - 방 5개 × 2,400초 = 1,080,000개 → ÷20 = **5.4만 건/수업**
  - 입력을 "바뀔 때만 + 최대 10Hz"로 바꾸면 약 **3.6만 건/수업**
- **보내는 메시지**(게스트에게 뿌리는 상태, 제일 큰 데이터)는 **무료**이고, 데이터 양 한도도 없습니다.
- **실행 시간**: 128MB × 2,400초 × 5방 ≈ 1,500 GB-초로, 13,000 한도의 12%입니다.
- **결론**: 하루 **1수업은 넉넉**하고, 입력 빈도를 줄이면 **하루 2수업**까지 됩니다. 하루 3수업 이상이면 부족합니다.
  - 그럴 때는 유료 Workers Paid(월 $5)로 가거나, 그날은 Firebase로 되돌아가는 **자동 대체 통로**를 둡니다.
  - 현재 코드는 이미 "직통 + Firebase 가산" 구조라 통로를 하나 더 얹기 쉽습니다.
- **주의 (미확인, 현장 확인 필요)**
  - 학교 망이 `*.workers.dev` 주소를 막는지
  - DO가 실제로 어느 도시에 배치되는지

### 3-4. 유료안 (비교용)

- **Firebase Blaze**: 다운로드 월 약 10GB 초과분부터 $1/GB입니다.
  - 지금 패킷 크기로 월 13수업(주 3회)이면 약 33~56GB가 나오고, 초과분 23~46GB → **월 약 $23~46**(추정)입니다.
  - 한도로 멈추지는 않지만 지연은 그대로입니다.
- **Cloudflare Workers Paid**: **월 $5**, 요청 월 1,000만 건이 포함되어 사실상 무제한 수업이 가능합니다.
- **Colyseus Cloud**: **월 $15부터**입니다.

## 4. 무료 추천안과 단계별 계획

### 추천: "Firebase는 로비·계정에 남기고, 게임 중계는 Cloudflare 무료 Durable Objects로" (방장 권한 구조 유지)

이 방안을 고른 이유는 다음과 같습니다.
- **무료**입니다.
- 한국과 가까워 **지연이 3~6배 줄 것으로 예상**됩니다.
- **계정 DB의 월 한도를 게임이 잡아먹지 않습니다.**
- 한도를 넘어도 **다음 날 아침 9시에 회복**되고, 그동안은 Firebase로 자동 대체됩니다.
- 게임 규칙 코드를 서버로 옮길 필요가 없습니다.

| 단계 | 할 일 | 돈 | 비고 |
|---|---|---|---|
| **0. 측정** | Firebase 콘솔 사용량 확인(1-2 ①), 게임에 측정 표시(ping·흔들림·KB/초·방장 fps) 추가 | 0 | 선생님 확인 5분, 코드는 작업 갈래에서 |
| **1. 지금 코드 손질** | 원인 B(밀리면 최신만 보내기), C(입력 번호 + 화해), F(주기 누적), G(보간 여유 ~180ms, 탄 보간), H·I(직통 재연결), J·K(패킷 축소, 1v1 15Hz) | 0 | 이것만으로 "끌림·순간이동·한도 소진"이 크게 줄어듦. 하네스 `harness_online*.js`로 검증 |
| **2. 현장 확인** | 학교 크롬북에서 Cloudflare 테스트 페이지로 접속되는지, 왕복 몇 ms인지 측정(nettest 확장) | 0 | 막히면 여기서 멈추고 1단계만 유지 |
| **3. Cloudflare 중계 추가** | 선생님 Cloudflare 무료 계정에 방 중계용 DO를 배포하고, 게임에 세 번째 통로로 얹기(기존 직통·Firebase 유지, 같은 `_sq` 번호로 먼저 온 것만 적용) | 0 | 계정 생성·배포는 선생님 승인 후. main 배포와는 별개 |
| **4. 수업 시범 후 전환** | 한 반에서 시범 후 Firebase 게임 중계를 5Hz 대체 통로로만 남김 | 0 | 하루 요청 수를 Cloudflare 대시보드로 확인 |
| (선택) 5. 방장 넘겨받기 | 방장이 끊기면 다음 학생이 이어받기(원인 D) | 0 | 난이도 높음, 수요를 보고 결정 |

**선생님이 정하실 것**
- Firebase 콘솔 사용량 확인 결과
- 1단계 코드 작업을 진행할지
- Cloudflare 계정을 만들지(3단계)
